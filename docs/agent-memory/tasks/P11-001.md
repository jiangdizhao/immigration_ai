# P11-001 — Chinese-first Locale + Shared Public Shell Foundation

**Status:** PLANNED  
**Milestone:** Phase 11  
**Risk:** Medium-low if kept to shell/locale scope  
**Executor:** Cline or Codex  
**Authority:** `AGENTS.md`, `docs/architecture/SERVICE_PLATFORM_UI_REBASE_V1.md`, `docs/agent-memory/DECISIONS.md`

## Goal

Add the minimum production-grade site-locale foundation needed for Phase 11 and convert the shared site shell to Chinese-first behavior without changing legal/backend behavior.

This task is intentionally narrower than a public-page redesign.

## Scope

Implement a small site-locale layer with:

- locale type supporting `zh-CN` and `en`;
- default `zh-CN` for a user with no stored preference;
- a one-click language control in the shared header;
- persisted preference across normal navigation and reload;
- reusable translation dictionary/helpers for shared shell copy;
- Chinese-first labels for shared header/footer/account-shell text where safe;
- English shell copy when switched to English.

Use the existing Next.js architecture. Do not introduce a second frontend framework.

The initial implementation should avoid locale-prefixed routes.

## Required behavioral constraints

1. **UI locale only.**  
   Do not change question-language detection, response-language selection, model prompts, legal-service payload semantics, or answer-lane behavior.

2. **Auth must survive.**  
   Login/register/account menu, admin/lawyer links, VIP status, guest handling and logout behavior must continue to work.

3. **Routes must survive.**  
   Existing links and redirects must remain valid. Do not rename routes in this task.

4. **No backend work.**  
   Do not edit `legal-service/`.

5. **No DB work.**  
   Do not add migrations or alter schema.

6. **No prototype factual claims.**  
   Do not add lawyer credentials, office addresses, success rates, SLA claims or testimonials from the temporary UI.

7. **No page-wide redesign.**  
   Home, Services, Process, Contact and AI Workspace remain for later Task Packets except where shared shell integration requires a minimal compatibility adjustment.

## Implementation guidance

Prefer a small typed locale module/provider over scattered inline bilingual strings.

The implementation should make later P11-02/P11-03 translation work straightforward.

Keep the locale state/client persistence mechanism simple and auditable. If a cookie is used, do not introduce server-side routing semantics in this task.

Do not make UI locale a source of truth for backend response language.

## Acceptance criteria

- Fresh browser/session with no stored site-locale preference renders the shared shell in Chinese.
- User can switch to English in one action.
- User can switch back to Chinese.
- Preference persists across reload and navigation.
- Desktop and mobile header both expose a usable language switch.
- Account menu still displays the correct role/membership behavior.
- Guest/login/register behavior remains intact.
- `/ai-workspace`, `/services`, `/process`, and `/contact` navigation remains valid.
- No legal-service or database files changed.
- No answer-mode behavior changed.
