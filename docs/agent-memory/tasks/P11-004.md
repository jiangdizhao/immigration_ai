## Goal

Rebase the production AI Workspace into the Chinese-first service-platform experience while preserving all existing functional behavior.

This is a presentation/information-architecture task around a high-blast-radius component. The current working controller is production authority.

## Design authority

Use the temporary V4 workspace only as a visual/journey reference.

Adopt the useful direction:

- dense operational workspace instead of public marketing layout;
- strong left conversation/navigation region;
- central consultation/chat region;
- right matter/source/handoff context region;
- Deep Navy platform chrome, restrained AI accent, clear human-service distinction.

Do not copy V4 mock claims, credentials, cloud-terminal claims, fake matter data, or backend behavior.

## Locale rule

Static workspace UI follows the existing site locale:

- default `zh-CN`;
- one-click English through the existing `SiteLanguageSwitcher`;
- no locale route prefix migration.

Site locale does NOT control the assistant answer language.

A Chinese shell must still display an English answer when the backend answered English, and vice versa.

## Stage 1 — current executable stage

Implement the structural/bilingual rebase.

### Required result

1. Remove or substantially collapse the current duplicate marketing-style hero treatment around the workspace.
2. Keep the shared production `SiteHeader` and its auth/account/locale behavior.
3. Re-present answer mode as a compact workspace control while preserving the exact access-policy logic and disabled states.
4. Reorganize the existing workspace into an operational three-region desktop layout:
   - conversation/history region;
   - active consultation/chat region;
   - matter/facts/sources/lawyer-handoff region.
5. Preserve all existing actions and data paths; presentation may move, behavior may not be silently rewritten.
6. Make visible static workspace chrome Chinese-first and bilingual.
7. Keep response-language-specific answer/progress content logically separate from site-locale copy.
8. Make the layout functional at desktop, tablet and narrow mobile widths. Final exhaustive responsive/accessibility acceptance remains P11-008.
9. Preserve or intentionally retain stable test IDs used by current tests.
10. Do not implement the real booking workflow. A booking placeholder may remain clearly non-production, or the presentation may point users to the existing lawyer-request path where semantically correct, but do not invent calendar availability.

### Preferred code shape

Avoid a second monolithic rewrite.

It is acceptable to:

- add a focused `workspace-copy` / typed translation module;
- extract presentation-only subcomponents if this reduces risk;
- keep stateful controller/network actions in the existing workspace component unless a move is demonstrably behavior-preserving.

Do not refactor backend-facing logic merely for style.
