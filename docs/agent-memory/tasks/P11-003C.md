## Goal

Add the first automation layer to Policy Intelligence:

```text
allowlisted official source
    -> operator-run discovery
    -> non-public candidate artifact
    -> human verification
    -> manual editorial entry
    -> existing publication gate
```

P11-003C automates **discovery only**.

It must not automate interpretation, approval, or publication.

## Core invariant

A discovery result is NOT a `PolicyEntry`.

It is a non-public candidate/evidence artifact.

The discovery layer must not silently decide:

- whether a policy is legally in force;
- whether it applies to a particular visa/person;
- what its legal effect is;
- what the bilingual public summary should say;
- whether it should be published.

Those remain human editorial/legal decisions.

## Source allowlist

Create a small Policy Intelligence discovery-source configuration.

Do not invent arbitrary domains.

Initial source hosts must be grounded in official sources already recognised in the repository, especially the existing official-source registry.

Prefer the smallest useful initial set, such as official Home Affairs, Federal Register of Legislation and ART source hosts already represented in repository authority.

Each source configuration should identify, as applicable:

- stable source ID;
- authority name;
- allowed hostnames;
- bounded seed/discovery URLs;
- discovery strategy;
- optional category/topic hint.

Do not add non-official media/blog/community sources.

If a useful new domain is not already grounded in repository authority, STOP and ask the owner.

## Strict fetch boundary

Implement a bounded fetch utility for the operator-run discovery tool.

Requirements:

- HTTPS only;
- hostname must match the configured allowlist;
- redirects must be revalidated against the allowlist;
- finite timeout;
- finite maximum response bytes;
- bounded redirect count;
- accepted content types explicitly constrained;
- descriptive user agent;
- no credential/cookie forwarding;
- no arbitrary localhost/private-network URLs;
- no user-supplied free-form URL that bypasses source configuration.

If the current runtime APIs make redirect revalidation awkward, implement the safest bounded strategy and document it.

This is not an SSRF-capable generic URL fetcher.

## Discovery candidate contract

Create an internal non-public candidate type/schema, separate from `PolicyEntry`.

Use a versioned contract, conceptually:

`policy-intelligence.discovery-candidate.v1`

It should capture factual acquisition metadata only, for example:

- candidate ID;
- source config ID;
- authority;
- canonical official URL;
- discovered title if present;
- discovered/published date only when explicitly available;
- retrieval timestamp;
- content type;
- bounded source text/description preview if useful;
- content fingerprint/hash;
- source metadata such as ETag/Last-Modified when available;
- discovery method/strategy;
- evidence/provenance fields needed for human review.

Do NOT put generated legal analysis or lawyer commentary into the candidate.

Do NOT require a `PolicySourceStatus` legal classification in the candidate.

If explicit source metadata states a status, preserve it as raw evidence rather than converting it automatically into the production status enum unless the mapping is unquestionably mechanical.

## Candidate persistence

Discovery must never write directly to:

`chatbot/content/policy-intelligence/registry.ts`

Create a separate non-public candidate output location or output abstraction.

Preferred behavior:

- operator CLI supports dry-run/stdout;
- optional explicit output writes candidate JSON artifacts to a clearly non-public discovery/candidate directory;
- the application must not import that candidate directory;
- candidate artifacts must not become public page props;
- no runtime web request should write files in deployed production.

Choose a repository/local-workflow layout that is easy to inspect and does not risk accidental public bundling.

Document whether generated candidate files are intended to be committed for review or kept local. Keep the choice simple and explicit.

## Discovery strategy

Do not build a general web crawler.

Implement narrow adapters/strategies suitable for configured official sources, for example:

- bounded sitemap/listing discovery;
- bounded seed-page link discovery;
- direct configured page metadata retrieval.

Prefer structured metadata when available.

Limit:

- number of fetched pages per run;
- link fan-out;
- total bytes;
- runtime duration.

No recursive unlimited crawl.

## Canonicalisation and deduplication

Add deterministic helpers for:

- URL canonicalisation;
- stable candidate ID generation;
- content fingerprint/hash;
- duplicate candidate suppression within a run.

Do not collapse genuinely distinct official URLs merely because titles are similar.

Tests must prove deterministic behavior.

## Operator CLI

Add an offline/operator command, conceptually:

```bash
pnpm policy:discover -- --source <source-id> --dry-run
```

Exact command naming is your technical choice.

Requirements:

- no execution from public page requests;
- source must be selected from configured allowlist;
- clear dry-run mode;
- bounded result count;
- machine-readable output plus concise human summary;
- non-zero exit for invalid source/config/fetch contract violations;
- no publication side effects.

A live network smoke test is OPTIONAL and must not be required for deterministic test success.

If the coding sandbox/network cannot reach official sites, do not weaken tests or source controls.

## Deterministic fixtures

All unit/integration tests for parsing/discovery behavior must use local fixtures.

Add representative fixture documents for the strategies you implement, such as:

- sitemap XML;
- official listing HTML;
- official detail HTML/metadata.

Fixtures must be synthetic/structural, not claims about current Australian policy.

No test may require internet access.

## Promotion boundary

There must be no function such as:

`publishCandidate()`

that directly makes a candidate public.

At most, documentation may describe the manual handoff:

```text
candidate
 -> verify official source
 -> manually author/review PolicyEntry
 -> review_required
 -> approval
 -> published
```

Do not automate candidate-to-public-copy conversion in P11-003C.
